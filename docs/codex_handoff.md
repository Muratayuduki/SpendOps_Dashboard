## 最新仕様の要点

- 個人用途の家計簿・資産管理ダッシュボードから、複数人のCSVを収集して分析する比較分析サービスへ方向転換する
- 各ユーザーがCSVをアップロードし、システムが正規化、月次集計、匿名化集計を行う
- 各ユーザーのデータを集計し、MVPでは月間支出、カテゴリ別支出、支払い方法別支出、取引件数、前月比、全体平均との差を比較できるようにする
- 中央値と分位はMVP対象外とし、利用者数が増えてから追加する
- 比較分析は、原則として匿名化・集計値ベースで行い、生データの横並び表示は避ける
- 初期版ではPayPay、JCB、三井住友VISAの3種類のCSV分析を行う
- 横浜銀行を含む銀行CSV対応は今回の開発対象外とし、ガントと残作業から除外する
- MyJCBとSmartHRはローカルChromeのログイン済みセッションから自動取得できることを確認済みだが、多人数版MVPではCSVアップロードを基本にする
- Cognitoで一般ユーザーと管理者を分ける
- 一般ユーザーは本人データのみ、管理者は全体集計・取込状況・エラー原因ファイルの特定のみ行う
- 管理者も個人情報、生明細、CSV原本は閲覧できない
- 原本CSV、ファイル名、未加工行は保存せず、DynamoDBには正規化済み個別取引、月別集計、取込記録、本人別の分類ルールを保存する。分類ルールには利用先名そのものを保存しない
- ユーザー登録時に、収支データを匿名化・集計して比較分析へ利用する同意を取る
- 退会時は本人に紐づく個別取引、月別集計、取込記録、ユーザー情報を削除し、再識別できない全体集計のみ残す
- CSV取込は部分取込を許可し、該当行以外を取り込んだうえで失敗行番号と理由を表示する
- 氏名、商品名、CSV未加工行、カード番号、口座番号、認証情報はDynamoDBへ保存しない。利用先は本人の明細復元に必要な正規化項目として保存する
- 比較対象は同じデータソース同士から開始し、最終的には全支出を統合した比較分析を目指す
- 取引明細はブラウザで正規化して日付単位で保存し、分析・画面表示・他者比較は月別集計を中心にする
- 収入・支出・資産推移を、個人内推移と集団平均との差の両方で見られるようにする
- AWS Cost ExplorerによるAWS料金取得は初期版から削除する。複数人の収支CSV比較分析に集中する
- AWS基盤はTerraformで管理する。2026-07-22に再構築した基盤は、Planとユーザー承認を経て2026-07-23に全削除した。今後の再構築・変更・デプロイもPlan確認とユーザー承認後に行う
- 2026-07-23時点でTerraform stateは0件。ローカルのコード、資料、Terraform定義、draw.ioは保持している

## 2026-07-08 要件整理履歴

2026-07-08時点で、サービス方針を個人資産管理から複数人CSV比較分析サービスへ切り替えた。

今回確定した内容:

- 初期版はPayPay、JCB、三井住友VISAの3種類のCSV分析を行う
- PayPay CSVはUTF-8で、1行目にヘッダーがある
- PayPay CSVでは、取引日、出金金額、入金金額、取引内容、取引先、取引方法、支払い区分、利用者、取引番号を確認済み
- JCB CSVはShift_JISで、先頭に支払日・支払金額合計などのメタ情報があり、明細ヘッダー行まで読み飛ばす必要がある
- JCB CSVでは、ご利用者、カテゴリ、ご利用日、ご利用先など、ご利用金額、支払区分、お支払い金額、摘要、備考を確認済み
- 三井住友VISA CSVはShift_JISで、先頭にカード情報系のメタ行があり、明細行は固定列として扱う必要がある
- 管理者も個人情報、生明細、CSV原本を閲覧できない
- 管理者が確認できるのは、全体集計、取込状況、エラー件数、エラー原因ファイル、失敗行番号、失敗理由に限定する
- 原本CSVは保存しない。取込時に読み取り、加工後の正規化済みデータだけ保存する
- 氏名は削除する
- 支出先、摘要、取引内容はカテゴリ分類に必要なため保存する
- ユーザー登録時に、匿名化・集計して比較分析へ利用する同意を取る
- 退会時は本人に紐づく月別集計、取込記録、ユーザー情報を削除する
- 退会後も、個人を再識別できない全体集計だけ残す
- CSV取込は部分取込を許可する
- 取込に失敗した行は除外し、それ以外の行で集計する
- 画面には「何行目のデータ取得に失敗したため、それ以外で集計を行います」という趣旨のエラーを表示する
- MVPでは中央値と分位は表示しない
- MVPの分析項目は、月間支出総額、月間収入総額、カテゴリ別支出、支払い方法別支出、取引件数、前月比、全体平均との差とする
- 初期の比較対象は同じデータソース同士にする
- 最終的にはPayPay、JCB、VISAなどを統合した全支出比較を目指す
- AWS Cost ExplorerによるAWS料金取得は初期版から削除し、AWSは認証、保存、集計、監査、暗号化の実行基盤として使う
