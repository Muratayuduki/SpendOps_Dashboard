# SpendOps Dashboard アクティブガードレール

更新日: 2026-08-01（Asia/Tokyo）

このファイルには、すべてのリポジトリ作業で常時適用する規則だけを置く。設計背景、旧テンプレート、過去仕様は`project-guidance/archive/system_prompt_guardrails_v2.md`を必要時だけ参照する。

## 基本行動

- ユーザーの目的、指定範囲、完了条件を優先する。
- 既存コード、資料、変更中のファイルを確認し、他者の変更を戻さない。
- 軽微な不明点は仮定を明示して進める。成果物を大きく変える不明点だけ確認する。
- 結論、変更内容、検証結果、未確認事項を簡潔に報告する。
- 最新・変更され得る外部情報が必要な場合は、公式情報を優先して確認する。

## ローカル自動実行

- 読み取り、検索、コード・資料編集、テスト、lint、build、Terraform fmt・validate・state確認・Plan作成は、依頼範囲内で承認を求めず進める。
- `.codex/config.toml`の`approval_policy = "never"`と`workspace-write`を維持する。
- 権限昇格やネットワークなしで実行できない項目は迂回せず、未確認として報告する。

## 明示的な実行依頼が必要な操作

次の操作は、一般的な承認プロンプトとは別に、ユーザーの今回の依頼にその操作が明示されている場合だけ実行する。

- Terraform Apply、Destroy、削除保護解除
- AWSリソース、IAM、Cognito、公開範囲、秘密情報の変更
- 本番デプロイ、外部公開、Cloudflare DNS変更
- 外部サービスへの書込み・送信
- 復旧困難な削除や上書き

Terraformでは必ず現在のコードから新しいPlanを作り、追加・変更・削除・置換・料金・権限・公開範囲への影響を示す。過去のPlanや直接の`terraform destroy`を使わない。

## データ保護

- 実CSVは通常読まない。必要な場合も内容を会話、ログ、資料、テスト出力へ転記しない。
- 氏名、メール本文全文、利用明細、利用先、金額、カード番号、口座番号、パスワード、認証コード、トークンを保存・出力しない。
- CSV原本、ファイル名、未加工行をAWSへ送信・保存しない。
- 秘密情報をコード、Git、Terraform、資料へ直書きしない。
- CloudWatch Logsや診断出力へリクエスト本文・取引内容を出さない。

## 変更と検証

- 変更範囲を必要最小限にし、無関係な整形や大規模リファクタリングを混ぜない。
- 依存関係の追加は必要性と影響を確認し、依頼範囲を超える場合は実施しない。
- 実装後は関連テストを行い、実行できなかった検証を成功扱いにしない。
- 「実装済み」「現在利用可能」「停止中」「未実装」「提出時予定」「将来候補」を区別する。
- READMEと競合する記述を発見した場合は、READMEを正本として競合を報告する。
